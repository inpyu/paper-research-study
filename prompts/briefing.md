아래 신규 논문들을 이 연구의 관점에서 브리핑하라.

## 이 연구의 가설

## 연구 전제
- 환경: GPU 없음 / CPU only / 1GbE 이더넷 / 프롬프트 0.5~4K 토큰
- 목표 지표: TTFT (prefill 시간이 거의 전부를 차지)
- 이미 아는 선행연구: {SEED_TITLES}

## 논문 목록
{PAPERS}

## 출력 형식
아래 JSON만 출력하라. 설명이나 코드펜스 없이 JSON 객체 하나만.

{"briefings":[{"id":"<위 목록의 id 그대로>","what":"<무엇을 했나. 한 문장>","relation":"<우리 가설 중 무엇을 보강/위협하나, 또는 왜 무관한가. 한 문장>","gap":"<우리 체제와의 간극. 전제가 어디서 깨지는가. 한 문장. 무관하면 빈 문자열>","verdict":"must-read|skim|skip","hypotheses":["H1"],"topics":["<주제 태그 2~4개>"]}]}

## verdict 기준 — 중요
이 연구는 선행연구를 `refs.md` 표에 "논문 | 요지 | **우리와의 간극**" 형식으로 추적한다.
따라서 **전제가 다르다는 것 자체는 skip 의 이유가 아니다.** 오히려 그게 간극 열의 내용이 된다.

- **must-read**: 우리 가설을 직접 보강하거나 위협한다. 또는 우리가 하려는 것을 이미 했다(선점 위험).
- **skim**: 같은 문제(prefill 파이프라인 버블, 청크 스케줄링, KV 재사용/압축, 통신-연산 오버랩,
  병렬 인코딩, CPU/엣지 추론)를 다룬다. **GPU·NPU·초장문 전제라도 문제가 같으면 skim 이상이다** —
  전제가 깨지는 지점을 gap 에 적으면 그대로 refs.md 한 줄이 된다.
- **skip**: 문제 자체가 다르다(예: vision 전처리, 학습 기법, 데이터 파이프라인).
  또는 초록만으로는 판단 근거가 전혀 없다.

## 규칙
- 제목·저자·수치는 위에 주어진 것만 쓴다. 새로 만들지 않는다.
- 초록에 없는 내용을 추측해 쓰지 않는다.
- hypotheses는 관련된 것만. 없으면 빈 배열.
- topics 는 논문의 주제를 나타내는 일반 용어로 쓴다.
  예: KV cache, attention, prefill, 파이프라인 병렬, 텐서 병렬, 양자화, 스케줄링,
      long-context, 통신 최적화, 엣지 추론, 서빙 시스템, 투기적 디코딩
  arXiv 분류코드(cs.LG 등)나 가설 번호는 topics 에 넣지 않는다.
- 한국어로 쓴다. 각 문장은 간결하게.
