# 레포 위키 — 파싱 부산물을 학습 자료로

개념·갭·논문 말고도, 레포를 파싱하면 **그 자체로 배울 거리가 되는 정보**가 쏟아진다.
DeepWiki류가 "코드 설명"에서 멈추는 데 반해, 여기서는 **위키 페이지마다 갭과 퀴즈가 붙는다.**

아래는 전부 `prefill-opt`를 실제로 훑어서 확인한 수치다(2026-09-01, `main`).

## 1. 위키 페이지 종류

각 페이지는 **파싱으로 뼈대를 만들고(LLM 미사용)**, 서술 문장만 헤드리스로 채운다.

### W1. 파일·모듈 페이지 (22쪽)
```
src/nn/nn-cpu-ops.cpp
├ 한 줄 역할        (노트 01-code-map에 있으면 그대로 인용, 없으면 생성)
├ 주요 함수 목록     tree-sitter 심볼 + 줄 범위
├ 누가 이 파일을 부르나 / 이 파일이 무엇을 부르나   (호출 관계)
├ 이 파일을 설명하는 노트   01-code-map 역방향 인덱스
└ 관련 개념           concept ↔ file 매핑
```
**노트에 없는 13개 파일이 여기서 처음 설명된다** — G1 갭의 해소 지점.

### W2. 실행 경로 페이지 ★ 이해도 상승폭이 가장 큰 페이지
"프롬프트 하나를 넣으면 무슨 일이 일어나는가"를 콜 체인으로 편다.
```
dllama.cpp: prefill 루프 (청크 단위 forward 반복)
  → llm.cpp: 모델 그래프 조립 (레이어별 op 나열)
    → nn-executor.cpp: 세그먼트 실행 · 배리어
      → nn-cpu-ops.cpp: 커널
      → nn-network.cpp: syncWait / syncXfer
```
각 단계에 **노트의 어느 문서가 이 단계를 설명하는지**와 **어느 로그 라인이 여기서 찍히는지**를 붙인다.
노트 `understand/01-code-map.md`가 이미 이 대응의 절반을 손으로 만들어 놨다 — 나머지를 자동으로 채운다.

### W3. 플래그 사전 (70개) — 즉시 효용이 큼
```
--cp-split
├ 정의 위치      app.cpp:NNN
├ 기본값·허용값   파싱
├ 코드에서의 영향  이 값을 읽는 지점들 (grep + 심볼 추적)
├ 노트 설명      있으면 인용 / 없으면 "문서 없음" 배지 + 생성된 설명
└ 실제 사용 이력  artifacts/*/raw/*.log, prefill_bench/*.sh 에서 이 플래그가 쓰인 run-id
```
"이 실험은 어떤 스위치를 켜고 잰 것인가"가 한 화면에서 답해진다. **48개가 지금 미문서 상태다.**

### W4. 실험 카드 (run-id 16개)
```
b_axis_v2
├ 언제·어느 커밋   manifest.json: git_sha 54787ee, dirty=true, 2026-08-20T14:31Z
├ 하드웨어 조건    hosts.tsv: 3노드 × 4코어, ondemand, 2.4GHz, 52~58℃
├ 실행 명령·플래그  raw 로그 헤더에서 복원 (pp=8 sp=1 tp=1 …)
├ 핵심 수치        derived/*.tsv 파싱
├ 이 실험을 인용하는 노트  refs 역인덱스
└ 주의            dirty=true → 커밋 안 된 변경이 섞임(dirty.patch 링크)
                  run-id에 inconclusive가 붙은 것은 결론 보류
```
`artifacts/README.md`가 "논문의 모든 수치는 run-id를 인용해야 한다"고 규정하고 있다.
위키가 그 인용 관계를 **양방향으로** 만들어 준다: 수치 → run-id → 조건 → 코드.

### W5. 로그 읽는 법
로그 라인 패턴을 클러스터링해 사전을 만든다.
```
"🧱 PP 레이어 불균등 분할: 8 8 8 8 8 8 8 8"
├ 찍히는 위치   app.cpp:NNN
├ 무슨 뜻       레이어를 노드에 어떻게 나눴는지
├ 이상 신호     합이 총 레이어 수와 다르면 분할 버그
└ 관련 개념     pipeline parallelism, PP 분할
```
로그 59개에서 반복되는 패턴만 추리면 사전은 수십 줄이면 끝난다.
**"로그를 읽을 줄 아는 것"이 이 연구의 실전 능력**이므로 학습 가치가 높다.

### W6. 수치 대사전
노트에 흩어진 실측값(447토큰 36.7초, 토큰당 0.5초, 가중치 6.3GB, machine balance 11–14 FLOP/byte,
타일 T≈22–28 …)을 한 곳에 모으고 **출처(문서·run-id)를 링크**한다.
같은 양이 문서마다 다른 값으로 적혀 있으면 **불일치 경고**를 띄운다 — 논문 쓸 때 바로 쓸모 있다.

### W7. 열린 질문
코드 TODO/FIXME 10개 + 노트의 "확인 필요"·"주의" 표현 + `*_inconclusive` run-id를 한 목록으로.

### W8. 용어 역인덱스
용어 하나에 대해 **노트 위치 · 코드 심볼 · 로그 라인 · run-id · 논문**을 한 번에 보여준다.
개념 페이지와 위키를 잇는 접착제.

## 2. 위키에서 자동으로 나오는 새 갭

기존 G1/G2/G3에 **문서화 갭**을 추가한다. 전부 LLM 없이 계산된다.

| 갭 | 정의 | 현재 `prefill-opt` |
|---|---|---|
| **G4 미문서 파일** | `src/**`에 있으나 어떤 노트도 언급하지 않는 파일 | **13 / 22** |
| **G5 미문서 플래그** | 코드에 있으나 노트에 없는 CLI 플래그 | **48 / 70** |
| **G6 고아 실험** | 어떤 노트도 인용하지 않는 run-id | 계산 대상 |
| **G7 출처 없는 수치** | 노트의 수치 중 run-id로 추적되지 않는 것 | 계산 대상 |
| **G8 불일치** | 같은 양이 문서마다 다른 값 | 계산 대상 |

G7·G8은 **논문 작성 리스크를 직접 줄인다.** `artifacts/README.md`의 자체 규칙을 기계가 검사해 주는 셈이다.

## 3. 학습 루프와의 연결

위키는 읽고 끝나는 문서가 아니다. 페이지마다 학습 장치가 붙는다.

```
위키 페이지 → "이 페이지에서 낼 수 있는 질문" 퀴즈 2~3문항
             (근거 = 그 페이지가 인용한 코드/로그/실험 그 자체)
          → 오답 개념은 복습 큐로
          → 페이지 하단에 "이걸 이해하려면 먼저 알아야 할 개념" (개념 그래프 링크)
```
예: W4 실험 카드의 퀴즈 — "`b_axis_v2`는 governor가 `ondemand`였다. 이 조건이 측정에 주는 영향은?"
→ 정답 근거는 `hosts.tsv`와 노트의 주파수 관련 서술. **실제로 논문 심사에서 물어볼 종류의 질문이다.**

## 4. 생성 비용

| 페이지 | 뼈대 | 서술 |
|---|---|---|
| W1 파일 (22) | 파싱 | 파일당 1회, 변경 시에만 재생성 |
| W2 실행 경로 (1~3) | 콜 그래프 | 코드 변경 시에만 |

한 번 만든 페이지는 **입력 해시가 바뀔 때만** 재생성한다. 정상 상태에서는 하루 몇 건이면 충분하다.

## 5. 정직한 한계

- **자동 생성 위키는 노트를 대체하지 않는다.** 노트에는 "왜 그렇게 했는가"가 있고, 위키에는 "무엇이 있는가"가 있다.
  위키 페이지에는 항상 **출처 배지**를 단다 — `노트 인용` / `파싱 사실` / `생성된 서술`.
- 생성된 서술은 틀릴 수 있다. 그래서 **파싱 사실과 생성 서술을 화면에서 분리해 표시**하고,
  생성 서술이 인용한 `file:line`은 루틴이 사후 검증한다.
- 호출 관계 추출은 C++ 매크로·간접 호출에서 불완전하다. 확신도를 함께 표시한다.
