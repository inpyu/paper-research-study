# RepoScholar (가칭) — 제품 기획서 v0.2

> 내가 연구 중인 레포를 등록하면, **연구 노트와 코드를 대조해 내가 모르는 것을 짚어주고**,
> 개념 학습 자료와 퀴즈를 만들고, **관련 연구를 매일 브리핑**해 주는 웹 + 네이티브 앱.

작성 2026-09-01 · **v0.3** (1인용 / 로컬 루틴 생성 + 정적 무중단 배포 / 네이티브 앱 / 대상 = `inpyu/prefill-opt`)

## 1. 확정된 전제

| 항목 | 결정 |
|---|---|
| 사용자 | **1인(본인) 전용.** 멀티테넌시·과금·팀 기능 없음 |
| 생성 | **이 서버의 cron 루틴이 Claude Code 헤드리스(구독)로 모든 콘텐츠를 미리 생성** |

## 2. 대상 레포를 실제로 열어본 결과 — 기획이 바뀐 이유

`prefill-opt`는 백지가 아니다. 이미 이런 것이 있다.

```
research/                 총 19,093줄의 손으로 쓴 연구 노트
├── README.md             프로젝트 개요
├── 00-RESEARCH-PLAN.md   문제 정의, 가설 H1~H5, 타겟 학회
├── 04-reading-path.md    Stage 0~N 단계별 논문 학습 경로 (★정독/○통독/△참조)
├── 08-glossary.md        용어집 — "정의보다 우리 측정값으로 설명"
├── refs.md               선행연구 표 (논문 · 요지 · 우리와의 간극)
└── understand/
    ├── 01-code-map.md    코드 지도
    ├── 04-concepts.md    개념 사전, 각 항목에 "← 이어지는 개념" 링크 (~1,900줄)
    ├── 05~09-math-*.md   수식 유도 문서 4종
    └── ...
src/, prefill_bench/, scripts/   실제 구현 (336 파일, 8.8MB)
```

**즉, 개념 그래프의 골격은 이미 사람이 만들어 놨다.** LLM으로 개념을 0부터 추출하는 설계는
여기서 비용만 쓰고 품질은 노트보다 못한 결과를 낸다. 그래서 파이프라인을 뒤집는다.

> **개정된 핵심 원칙 — 노트 우선(notes-first)**
> 1차 소스는 `research/*.md`다. 파싱은 **결정론적으로**(LLM 없이) 한다.
> LLM은 개념을 만들어내는 데 쓰지 않고, **빈틈을 찾아 메우고 · 퀴즈를 내고 · 논문을 브리핑하는 데만** 쓴다.

그리고 사용자가 말한 "기본 개념 학습에 부족함을 느낀다"는 감각은, 다음 세 가지 **갭**으로 정확히 계산할 수 있다.

| 갭 | 정의 | 의미 |
|---|---|---|
| **G1 설명 공백** | 코드 심볼·주석에는 나오는데 노트 어디에도 설명이 없는 개념 | 지금 막히는 지점. 최우선 학습 대상 |
| **G2 근거 없음** | 노트에는 있는데 코드에 대응 구현이 없는 개념 | 아직 구현 안 됨 / 순수 배경지식 — 구분해서 표시 |
| **G3 언급만 있음** | 노트에서 이름만 쓰이고 정의된 적 없는 개념 (예: 다른 문서가 전제하는 용어) | "안다고 착각하고 넘어간" 것. **이 사용자의 핵심 통증** |

여기에 **문서화 갭 G4~G8**이 더해진다 — 미문서 파일(현재 13/22), 미문서 CLI 플래그(48/70),
고아 실험, 출처 없는 수치, 문서 간 수치 불일치. 전부 파싱만으로 계산된다. → [레포 위키](05-wiki.md)

## 3. 핵심 시나리오

### A. 레포 등록 → 갭 지도
```
[서버 루틴, 매일 06:00]
1. git pull → research/*.md 파싱 → 개념·링크 추출        ← LLM 미사용
2. 코드 심볼 대조 → G1 / G2 / G3 갱신                     ← LLM 미사용
3. 새로 생긴 갭 상위 5개에 대해서만 설명·퀴즈 생성          ← Claude Code 헤드리스
4. site/public/data/*.json 갱신 → git push → Vercel 배포

[사용자, 아무 때나]
5. 앱/웹을 열면 이미 다 만들어져 있다. 대기 시간 0, 네트워크는 JSON 몇 KB
```

### B. 개념 학습 → 퀴즈
```
개념 상세 = ① 노트 원문 인용(있으면)  ② 코드 근거 file:line  ③ LLM 보충 설명(부족할 때만)
        ④ 이어지는 개념 링크(노트의 "← 이어지는 개념"을 그대로 활용)
퀴즈    = 노트 본문 + 코드 근거에서만 출제. 근거 없는 문항은 생성 금지
        모바일에서 카드 3장씩, 오답은 복습 큐로
```

### C. 매일 아침 논문 브리핑 (사용자가 명시 요청한 기능)
```
시드   : research/refs.md 의 논문 ~15편 + 가설 H1~H5 + 도메인 키워드
매일 1회: arXiv 신규 논문 검색(cs.DC, cs.LG, cs.AR) → 시드와 유사도 상위 3편
브리핑 : 편당 3문장 — ① 무엇을 했나 ② 우리 H1~H5 중 무엇을 보강/위협하나 ③ 읽어야 하나
전달   : 앱 푸시 알림 + 브리핑 히스토리 화면. 저장하면 refs.md 갱신용 마크다운 스니펫 제공
```
이 기능만으로도 서비스가 매일 열릴 이유가 된다. **리텐션의 핵심은 브리핑이지 퀴즈가 아니다.**

## 4. 기능 범위

### MVP (M1)
- 대상 레포 `git pull`(main, wcep)
- `research/*.md` 결정론적 파싱 → 개념·링크·논문 시드 추출
- 코드 심볼 인덱싱 → G1/G2/G3 갭 산출
- 갭 지도 화면(웹), 개념 상세(노트 인용 + 코드 근거)
- **레포 위키**: 파일·플래그·실험·로그·수치 페이지 (뼈대는 파싱만으로 생성)
- cron 루틴 + git push → Vercel 자동 배포 파이프라인

### v1 (M2)
- 개념 보충 설명 온디맨드 생성 / 퀴즈 생성·풀이·복습 큐
- 일 1회 논문 브리핑 + 푸시 알림(루틴이 직접 발송)
- 네이티브 앱(iOS/Android, 개인 배포)

### v2 (M3)
- 위키 페이지별 퀴즈, 수치 불일치 경고
- 브랜치 간 비교(`main` vs `wcep`에서 새로 등장한 개념)
- 커밋 push 시 증분 재분석, "이번 주 새로 생긴 갭"
- 브리핑을 `refs.md` PR로 자동 제안
- 노트↔논문 수식 대응(`05-math-attention.md` ↔ FlashAttention 논문)

### 비범위
- 멀티유저·과금·공개 서비스, 코드 자동 수정, 논문 전문 저장(링크·초록만)
- **런타임 LLM 호출** — 사이트에서 즉석 질의응답은 하지 않는다(과금 지점이 생기므로)

## 5. 성공 지표 (1인용이므로 지표도 개인적으로)

- **주 5일 이상 브리핑을 연다** ← North Star
- G3(언급만 있는 개념)와 G5(미문서 플래그) 개수가 **매주 줄어든다**
- 브리핑 논문 중 실제로 `refs.md`에 편입되는 비율 ≥ 20%
- 추가 LLM 비용이 **0원**이다(구조적으로 그래야 정상)
- 루틴 성공률 ≥ 95%, 실패 시 알림이 온다
- 루틴 1회 실행 ≤ 20분(타임아웃), 일반적으로 ≤ 5분

## 6. 리스크

| 리스크 | 대응 |
|---|---|
| **이 서버가 꺼지면** 데이터 갱신 중단 | 사이트는 정적이므로 계속 살아 있음. 화면에 "마지막 갱신 시각"을 항상 표시 |
| **Claude 구독 사용량 한도** 소진 | 루틴을 변경분만 처리하도록 가볍게 설계(하루 최대 5개 갱신). 실패해도 기존 배포 유지 |
| 헤드리스 인증 만료 | 루틴이 감지 → 알림 → 대화형에서 재로그인 |
| LLM 출력이 스키마를 어김 | 검증 실패 시 1회 재시도, 그래도 실패면 **직전 산출물 유지**. 깨진 데이터는 배포하지 않음 |
| LLM 환각(논문 제목 지어내기) | 논문은 arXiv API 응답에서만 취득. LLM은 요약만, 식별자 생성 금지 |
| 사용자 진도가 기기별로 갈림 | 1인용이므로 localStorage + JSON 내보내기/가져오기로 시작. 필요해지면 그때 DB |
| 노트가 한국어 + 수식 혼재 | 파서는 마크다운 구조만 신뢰, 자연어 해석은 LLM에 위임 |
| GitHub push 인증 미설정 | 착수 전 SSH 키 등록 또는 PAT 저장 (현재 미설정 상태) |
